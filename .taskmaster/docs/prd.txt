### 1.2 Current Workflow (Manual)
1. Targeted ads on Instagram (body massage, face massage, cleansing) for Abu Dhabi and Al Ain
2. Lead comes in via Instagram DM with a video showing the service/emirate
3. Admin sends quick response template based on the ad type
4. If client responds → collect name, WhatsApp number → transfer to salon admin
5. Admin contacts client via WhatsApp → proposes time slots, consults on services
6. Admin checks YClients for client history (previous services, active packages)
7. Admin confirms service, location, address
8. Booking created in YClients (without location)
9. Day before: confirmation message sent to client
10. Day of service: therapist views location, shares with driver
11. Therapist arrives → notifies admin → admin notifies client
12. After service: therapist confirms completion, reports payment method to admin
13. Admin records payment, marks booking complete in YClients

### 1.3 Problem
All of the above is done manually by 1-2 admins. The AI agent should automate steps 2-8 and partially step 9.

### 1.4 Goal
Build an AI WhatsApp agent that handles client communication, consultation, and booking for Crystal Lab. The agent should communicate naturally in English (primary) and Arabic, mimicking the current admin's communication style.

## 2. Product: AI WhatsApp Agent

### 2.1 Core Concept
An AI-powered conversational agent connected to WhatsApp that:
- Responds to incoming client messages 24/7
- Consults on services and prices
- Handles objections (e.g., "too expensive")
- Collects booking information (service, date/time, location)
- Creates bookings in YClients
- Sends confirmations
- Forwards leads/bookings to admin channel for oversight

### 2.2 What Already Exists (Prototype)
- Telegram bot prototype: @crystal_lab_bot (November 2025)
- Telegram leads channel: @crystal_lab_leads
- Message buffering system (7-second wait for multi-message clients)
- Express.js server skeleton with API routes
- Basic service structure (bookingService, whatsappService)

## 4. Business Rules for AI Agent

### 4.1 Client Communication Rules

1. **Language**: Primary communication in English. Agent should understand Arabic basic phrases and respond in English.

2. **Gender policy**: Crystal Lab is a women-only salon.
   - If the client is male with inappropriate requests → politely decline and block
   - Exception: wife booking for husband, couples massage, or existing male client already in YClients database
   - Always verify against YClients database before rejecting

3. **Returning clients**: Before responding, check YClients for client history:
   - Previous services and when
   - Active packages/subscriptions
   - Recommend based on previous visits
   - Watch for clients with unfinished packages (even if chat was cleared)

4. **Price communication**: Always state prices WITHOUT VAT, then add:
   - "Cash - tax free"
   - "Bank transfer + 5% VAT"

5. **Location info**: "We have a massage studio in Abu Dhabi, Al Raha. But it is currently closed for maintenance. We provide free transportation in Abu Dhabi and Al Ain."

6. **Message buffering**: Wait 7 seconds after receiving a message to collect all messages from client before responding (clients often send 3-4 messages in a row).

7. **Non-responsive clients follow-up**: If client doesn't respond, send a follow-up message after some time with a soft push:
   "All our therapists with medical education. Before the procedure will consult you, what kind of massage you need to achieve a quick and better result. The effect is already visible after 1 session. Would you like to try?"

### 4.2 Booking Process (Agent Flow)

1. Client initiates contact (from Instagram ad or direct WhatsApp)
2. Agent identifies the service interest (from ad context or client message)
3. Agent sends appropriate quick response template (body/face/cleansing)
4. Consultation: answer questions about services, techniques, prices
5. Handle objections if any (too expensive, what's included, etc.)
6. Collect booking info: service, preferred date/time, location/address
7. Check therapist availability in YClients
8. Confirm booking details with client
9. Create booking in YClients
10. Send confirmation to client using template
11. Forward lead/booking details to admin channel

### 4.7 Operational Rules

- **Notifications**: Booking confirmation sent to client 1 day before, once only
- **Drivers**: Do NOT send anything to drivers from the AI. Therapists handle their own locations and share with drivers directly. Drivers are Pakistani and communication through AI is too risky.
- **Schedule changes**: Bookings may be moved between therapists or rescheduled. Each change is handled individually, NOT via automated notifications.
- **Wait list**: If client needs a specific time and it's unavailable, add to wait list. When a cancellation happens, offer the slot to waiting clients.
- **Late arrivals**: Sometimes therapists are late (driver logistics). Admin manually notifies client about delays.
- **Upselling**: After confirming the main service, offer additional services and packages where appropriate.

## 5. Technical Architecture

### 5.1 Core Stack
- **Runtime**: Node.js 18+
- **Framework**: Express.js (already set up)
- **AI/LLM**: Claude API or OpenAI API for conversational intelligence
- **WhatsApp**: WhatsApp Business API (via official Cloud API or BSP like 360dialog)
- **Booking system**: YClients API
- **Database**: PostgreSQL (for local state, conversation history, client mapping)
- **Cache**: Redis (message buffering, rate limiting)
- **Hosting**: VPS or cloud (AWS/DigitalOcean)

### 5.2 Architecture

```
Instagram Ads → Client → WhatsApp
                            ↓
                   WhatsApp Cloud API (webhook)
                            ↓
                   Express.js Server
                            ↓
                   Message Buffer (Redis, 7 sec)
                            ↓
                   AI Agent (LLM + Knowledge Base)
                     ↙        ↓         ↘
              YClients API   Response    Admin Notification
              (check/book)   to Client   (Telegram/WhatsApp channel)
```

### 5.3 Key Components

1. **WhatsApp Webhook Handler** — receives incoming messages via Cloud API
2. **Message Buffer** — collects multi-part messages (7-sec window) via Redis
3. **Conversation Manager** — maintains conversation state per client
4. **AI Agent Core** — LLM-based agent with knowledge base (prices, scripts, rules)
5. **YClients Integration** — check availability, client history, create bookings
6. **Admin Notifier** — forwards leads and booking confirmations to admin channel
7. **Knowledge Base** — structured data: prices, offers, FAQ, objection scripts

### 5.4 Data Model

```
clients: { wa_phone, name, yclients_id, gender, first_contact_date, notes }
conversations: { client_id, messages[], state, current_intent, created_at }
bookings: { client_id, yclients_booking_id, service, datetime, location, status, payment_method, payment_status }
packages: { client_id, package_type, total_sessions, used_sessions, expires_at }
```

## 9. ManyChat Integration (Instagram DM + WhatsApp)

### 9.1 Overview

ManyChat serves as a middleware between Instagram DM / WhatsApp and our AI agent backend. This enables:
- Automated responses to Instagram DM leads from targeted ads
- Seamless handoff from Instagram to WhatsApp conversations
- Unified message processing through our existing AI agent

### 9.2 Architecture

```
Instagram Ads → Client → Instagram DM
                              ↓
                         ManyChat Platform
                    (Default Reply / Keyword triggers)
                              ↓
                    External Request (HTTP POST)
                              ↓
                    Our Python Backend (/manychat/webhook)
                              ↓
                    AI Agent (same logic as Telegram)
                              ↓
                    Response (ManyChat v2 Dynamic Content JSON)
                              ↓
                    ManyChat → Instagram DM / WhatsApp reply
```

### 9.3 ManyChat Integration Points

1. **External Request Webhook** — ManyChat sends incoming messages to our server via HTTP POST
   - URL: `https://<our-domain>/manychat/webhook`
   - Payload: subscriber_id, last_input_text, channel (instagram/whatsapp), first_name, custom fields
   - Response: v2 Dynamic Content JSON (text, buttons, images)
   - **Timeout: 10 seconds max** — response must be fast

2. **ManyChat API** (for proactive actions from our side)
   - Base URL: `https://api.manychat.com/fb/`
   - Auth: Bearer Token
   - Key endpoints: sendContent, sendFlow, subscriber management, tags, custom fields
   - Rate limit: 10 req/sec general, 25 msg/sec for sending

3. **Channel-specific rules**:
   - **Instagram DM**: 24-hour messaging window, no broadcasts, text + images + 3 buttons max
   - **WhatsApp**: 24-hour window, then only pre-approved Meta templates, requires ManyChat Pro ($15+/mo)

### 9.4 ManyChat Flows to Configure (in ManyChat UI)

1. **Default Reply** — catches all incoming messages, forwards to our webhook via External Request
2. **Instagram Ad Response Flows** — triggered by specific ad keywords:
   - Body massage ad → send body massage template → External Request to our agent
   - Face massage ad → send face massage template → External Request to our agent
   - Deep cleansing ad → send cleansing template → External Request to our agent
   - Welcome new follower → send welcome template → External Request to our agent
3. **WhatsApp Default Reply** — same pattern, forwards all messages to our webhook
4. **Instagram → WhatsApp Handoff Flow** — collects WhatsApp number in DM, triggers WhatsApp conversation

### 9.5 Response Format (v2 Dynamic Content)

Our webhook must return responses in this format:
```json
{
  "version": "v2",
  "content": {
    "messages": [
      {"type": "text", "text": "Response text here"}
    ],
    "actions": [
      {"action": "set_field_value", "field_name": "status", "value": "consulted"},
      {"action": "add_tag", "tag_name": "lead_from_instagram"}
    ]
  }
}
```
