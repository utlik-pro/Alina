# Сверка записей и отчёт по обращениям

Оба отчёта доступны только с `X-Admin-Secret` или `X-Manychat-Secret`.
Ключ передаётся в заголовке, не в URL. Отчёты не пишут клиентам и не меняют YClients.

## Отчёт по обращениям

`GET /admin/funnel-report?hours=24` (1–168 часов).

Локально: `python scripts/operations_report.py --hours 24`.
Для JSON добавьте `--json`. Нужен ключ в окружении/.env.

- Единица подсчёта — уникальный контакт за период, не сообщение или вызов модели.
- Записи считаются по уникальным сохранённым ID YClients. Конверсия — доля
  обращений, переданных агенту, у которых за этот период создана запись с ID.
- Записи вне когорты входящих обращений показаны в общем числе записей, но не
  увеличивают конверсию. Отменённые записи входят в число созданных, активные
  показаны отдельно. Наличие ID не означает, что все поля прошли сверку.
- Телефон «известен» может быть сохранён ранее, это не число новых телефонов.
- Очередь содержит этап остановки и следующее действие. Порог паузы — 30 минут;
  пауза не доказывает потерю клиента. Явная передача человеку, отказ, Шарджа и
  входящие вне рабочего окна выделены отдельно.
- Состояние берётся из последнего сохранённого контекста. Это операционный
  срез контактов, а не точная событийная воронка отдельных визитов.
- Источник — постоянная база. При сбое HTTP 503; при превышении лимита событий
  `truncated=true`, конверсия не рассчитывается. Тестеры и 770099xxx исключены.
- Телеметрия доставки WhatsApp добавлена в этом релизе. Исторический WhatsApp
  не восстанавливается из отсутствующих событий; старые периоды неполны.

Существующий `daily_report.py` использует этот источник метрик. Расписание и
рассылка не менялись. Новый `operations_report.py` только печатает результат.

## Сверка YClients

`GET /admin/reconciliation?limit=20&offset=0` (1–50 записей на страницу).
Локально: `python scripts/operations_report.py --reconcile --limit 20 --json`.
Следующая страница — `--offset` из `next_offset`.

Перед POST записи сохраняется `CalendarExpectation`: выбранный ID мастера,
ID услуг, время, длительность, имя, телефон, цена до НДС и способ оплаты.
Если сохранение не удалось, POST не отправляется. Новая таблица создаётся
обычным стартом приложения; старые записи не дополняются догадками.

Сравниваются дата/длительность, мастер, услуги, имя/телефон, цена услуг, маркер
операции, способ оплаты и условие НДС в комментарии, локальный статус оплаты
и `paid_full`. Последний не является проверкой банковской квитанции.

- `matches`: все проверяемые поля совпали.
- `recovered_matches`: запись найдена по маркеру после неопределённого исхода;
  её привязку к локальной записи должен проверить администратор.
- `mismatch`: хотя бы одно поле различается. Изменение администратором может
  быть намеренным — автоматически откатывать его нельзя.
- `needs_review`: данных не хватает, включая старые записи без снимка запроса.
- `unverified`: календарь недоступен, ответ неполон или не удалось проверить дату.

Сначала идут старые pending-попытки, затем failed и свежие accepted.
Неопределённость после POST не снимается по таймеру. Отчёт не повторяет POST,
не изменяет поля, не отмечает оплату и не связывает найденный ID автоматически.
