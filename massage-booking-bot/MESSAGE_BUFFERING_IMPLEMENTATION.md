# 🚀 Message Buffering System - Implementation

## 📋 Overview

Реализована система буферизации сообщений для обработки реального поведения клиентов, которые отправляют множественные сообщения подряд за 10-30 секунд.

---

## 🎯 Проблема (из анализа реальных чатов)

### ❌ БЕЗ буферизации:
```
Клиент: "Maybe 19th feb dear"
Бот: "What time would you like?" ← Отвечает СРАЗУ
Клиент: "Aroun 11" ← Уже отправил, но бот не видел
Клиент: "Its 1 hr rite?" ← И еще вопрос
Бот: ??? ← Не понимает контекст
```

### ✅ С буферизацией:
```
Клиент: "Maybe 19th feb dear"
Клиент: "Aroun 11"
Клиент: "Its 1 hr rite?"
[Бот ждёт 7 секунд]
Бот: "50 minutes for face massage. Your face massage is booked for 19 February at 11am 🌹"
← Обработал ВСЁ вместе!
```

---

## 🔧 Как работает система

### 1. **Глобальные структуры данных** (lines 28-31)

```python
message_buffers = {}  # {user_id: [messages]}
last_activity = {}    # {user_id: timestamp}
processing_tasks = {} # {user_id: asyncio.Task}
```

- `message_buffers` - хранит накопленные сообщения для каждого пользователя
- `last_activity` - время последнего сообщения (для проверки паузы)
- `processing_tasks` - активные задачи обработки (для отмены при новых сообщениях)

---

### 2. **Обработчик входящих сообщений** (lines 281-315)

```python
@router.message(F.text)
async def handle_message(message: Message) -> None:
    """
    НЕ обрабатывает сообщение сразу!
    Добавляет в буфер и запускает таймер на 7 секунд.
    """

    # 1. Добавить сообщение в буфер
    message_buffers[user_id].append(message)
    last_activity[user_id] = time.time()

    # 2. Отменить предыдущий таймер (если есть)
    if user_id in processing_tasks:
        old_task.cancel()

    # 3. Запустить НОВЫЙ таймер на 7 секунд
    task = asyncio.create_task(_process_buffered_messages(user_id, telegram_id, 7))
    processing_tasks[user_id] = task
```

**Что происходит:**
- Каждое новое сообщение **отменяет предыдущий таймер**
- Запускается **новый таймер** на 7 секунд
- Если клиент отправляет 3 сообщения за 10 секунд → таймер перезапускается 3 раза → обработка начнется через 7 секунд после **последнего** сообщения

---

### 3. **Обработка буферизованных сообщений** (lines 204-278)

```python
async def _process_buffered_messages(user_id: int, telegram_id: str, delay_seconds: int = 7) -> None:
    """
    Вызывается через 7 секунд после последнего сообщения.
    """

    # 1. Ждем 7 секунд
    await asyncio.sleep(delay_seconds)

    # 2. Проверяем что нет новых сообщений за последние 7 секунд
    if time.time() - last_activity[user_id] < delay_seconds:
        return  # Клиент еще пишет, выходим

    # 3. Получаем все накопленные сообщения
    messages = message_buffers[user_id]

    # 4. Комбинируем все тексты в один
    combined_text = "\n".join(msg.text for msg in messages)

    # 5. Предобработка ВСЕХ сообщений
    for msg in messages:
        await _preprocess_user_input(..., msg.text, ...)

    # 6. Отправляем комбинированный текст в GPT
    bot_response = await booking_agent.process_message(combined_text, context)

    # 7. Отвечаем на ПОСЛЕДНЕЕ сообщение
    await messages[-1].answer(bot_response)

    # 8. Очищаем буфер
    message_buffers[user_id] = []
```

## 📊 Примеры работы

### Пример 1: Множественные сообщения с датой и временем

**Клиент отправляет:**
```
[00:00] "Maybe 19th feb dear"
[00:10] "Aroun 11"
[00:28] "Its 1 hr rite?"
```

**Что происходит:**
1. `00:00` - Сообщение 1 добавлено в буфер, таймер запущен на 7 сек
2. `00:10` - Сообщение 2 добавлено, **таймер ПЕРЕЗАПУЩЕН** на 7 сек
3. `00:28` - Сообщение 3 добавлено, **таймер ПЕРЕЗАПУЩЕН** на 7 сек
4. `00:35` (через 7 сек после последнего) - Обработка начинается

**GPT получает:**
```
Maybe 19th feb dear
Aroun 11
Its 1 hr rite?
```

**GPT понимает:**
- Дата: 19 февраля
- Время: 11:00
- Вопрос о длительности: 1 час?

**Ответ:**
```
50 minutes for face massage. Your face massage is booked for 19 February at 11am 🌹
```

---

### Пример 2: Изменение решения

**Клиент отправляет:**
```
[00:00] "Body"
[00:04] "Both"
```

**Что происходит:**
1. `00:00` - "Body" добавлен в буфер
2. `00:04` - "Both" добавлен в буфер, таймер перезапущен
3. `00:11` - Обработка

**GPT получает:**
```
Body
Both
```

**Preprocessing обнаруживает:**
- Первое сообщение: `service_type = "Body massage"`
- Второе сообщение: `service_type = "Body + Face"` (ПЕРЕЗАПИСЫВАЕТ)

**Итог:** Booking создается для "Body + Face" (последнее решение клиента)

---

### Пример 3: Всё сразу (локация + номер виллы)

**Клиент отправляет:**
```
[00:00] [GPS Location]
[00:01] "Villa 20"
[00:01] [Photo виллы]
```

**Что происходит:**
1. Location handler обрабатывает GPS сразу (не буферизуется)
2. "Villa 20" добавляется в текстовый буфер
3. Photo handler обрабатывает фото сразу (не буферизуется)
4. Через 7 секунд обрабатывается "Villa 20"

**Результат:**
- GPS сохранен: `location_latitude`, `location_longitude`
- Номер виллы сохранен: `location_details = "Villa 20"`
- Фото сохранено в БД

## ⚙️ Конфигурация

### Параметр задержки: `delay_seconds = 7`

Почему 7 секунд?
- Анализ реальных чатов показал: 10-38 секунд между сообщениями
- 7 секунд достаточно для большинства случаев
- Не слишком долго для клиента

**Можно изменить в коде:**
```python
# bot.py line 314
task = asyncio.create_task(_process_buffered_messages(user_id, telegram_id, delay_seconds=7))
```

Рекомендации:
- **5 секунд** - более быстрый отклик, но может прервать быстрого печатающего клиента
- **7 секунд** - баланс (текущее значение)
- **10 секунд** - более надежно для медленных клиентов, но дольше ожидание

## 📈 Метрики для мониторинга

### Логи для анализа:

```python
# При добавлении в буфер
logger.debug(f"User {user_id}: добавлено в буфер ({len(message_buffers[user_id])} сообщений)")

# При отмене предыдущей задачи
logger.debug(f"User {user_id}: отменена предыдущая задача обработки")

# При обработке буфера
logger.info(f"User {user_id}: обработка {len(messages)} накопленных сообщений")
logger.info(f"User {user_id}: комбинированный текст: {combined_text}")
```

### Что проверять в логах:

1. **Количество буферизованных сообщений:**
   - 1 сообщение = клиент пишет по одному (нормально)
   - 2-4 сообщения = реальный паттерн множественных сообщений (ожидаемо)
   - 5+ сообщений = клиент очень медленно печатает или копирует текст

2. **Комбинированный текст:**
   - Должен содержать ВСЕ сообщения клиента
   - Разделены `\n` (новая строка)

3. **Ошибки:**
   - `NoneType` ошибки должны исчезнуть (все данные извлекаются до GPT)
   - Дублирование вопросов должно исчезнуть (GPT видит полный контекст)

## ⚠️ Потенциальные проблемы и решения

### Проблема 1: Бот отвечает слишком медленно

**Симптом:** Клиент жалуется на задержку ответа

**Решение:** Уменьшить `delay_seconds` с 7 до 5 секунд
```python
task = asyncio.create_task(_process_buffered_messages(user_id, telegram_id, delay_seconds=5))
```

---

### Проблема 2: Бот всё равно пропускает сообщения

**Симптом:** В логах видно 1 сообщение, но клиент отправил 3

**Причина:** Клиент печатает ОЧЕНЬ медленно (более 7 секунд между сообщениями)

**Решение:** Увеличить `delay_seconds` до 10 секунд

---

### Проблема 3: Бот обрабатывает неполный контекст

**Симптом:** GPT не видит последнее сообщение

**Причина:** Таймер сработал до добавления последнего сообщения (race condition)

**Решение:** Проверка `time.time() - last_activity[user_id] < delay_seconds` предотвращает это
