# 🧪 Message Buffering - Quick Test Guide

## 🎯 Цель тестирования

Убедиться, что бот правильно обрабатывает множественные сообщения от клиентов, которые приходят за 10-30 секунд.

---

## ⏱️ Как работает буферизация

```
Клиент: "Body massage"          [00:00] ← Сообщение 1
   ↓
[Бот молчит, ждет...]
   ↓
Клиент: "90 min"                 [00:03] ← Сообщение 2 (через 3 секунды)
   ↓
[Таймер перезапущен, бот ждет еще 7 секунд...]
   ↓
Клиент: "tomorrow 3pm"           [00:08] ← Сообщение 3 (еще через 5 секунд)
   ↓
[Таймер перезапущен, бот ждет еще 7 секунд...]
   ↓
[Пауза 7 секунд без новых сообщений]
   ↓
Бот: "Could you send your location..." [00:15] ← Ответ через 7 сек после последнего
```

**Итого:** Бот подождал 15 секунд и обработал ВСЕ 3 сообщения вместе!

---

## ✅ ТЕСТ 1: Базовый тест множественных сообщений

### Шаги:

1. Отправьте `/start` в Telegram боту
2. Отправьте **быстро** (в течение 10 секунд) три сообщения:
   ```
   Body massage
   ```
   (подождите 3 секунды)
   ```
   90 min
   ```
   (подождите 3 секунды)
   ```
   please
   ```

3. **НЕ отправляйте больше ничего**, просто ждите

### ✅ Ожидаемое поведение:

- Бот **НЕ отвечает** сразу после первого сообщения
- Бот **НЕ отвечает** сразу после второго сообщения
- Бот **НЕ отвечает** сразу после третьего сообщения
- Через **~7 секунд** после последнего сообщения бот отвечает:
  ```
  Could you send your location please? I will check availabilities
  ```

### ❌ Неправильное поведение:

- Бот отвечает сразу после первого сообщения ("Which duration?")
- Бот отвечает дважды
- Бот не видит все три сообщения

---

## ✅ ТЕСТ 2: Изменение решения

### Шаги:

1. Отправьте `/clear` для очистки контекста
2. Отправьте `/start`
3. Отправьте **быстро** (в течение 5 секунд):
   ```
   Body massage
   ```
   (подождите 2 секунды)
   ```
   Both massage please
   ```

4. Дождитесь ответа бота (7 секунд)

### ✅ Ожидаемое поведение:

- Бот молчит 7 секунд
- Бот спрашивает про локацию
- В логах ([bot.log](bot.log)) видно:
  ```
  User {id}: обработка 2 накопленных сообщений
  User {id}: комбинированный текст: Body massage
  Both massage please
  ```
- **ВАЖНО:** Preprocessing должен установить `service_type = "Body + Face"`, а не "Body massage"

### ❌ Неправильное поведение:

- Бот выбрал "Body massage" (первое сообщение) вместо "Body + Face" (последнее)
- Цена 483 AED вместо 619.50 AED

---

## ✅ ТЕСТ 3: Одно сообщение (регрессия)

### Шаги:

1. Отправьте `/clear`
2. Отправьте `/start`
3. Отправьте **одно** сообщение:
   ```
   Body massage 90 min
   ```

4. **НЕ отправляйте больше ничего**

### ✅ Ожидаемое поведение:

- Бот молчит **7 секунд**
- Потом отвечает: "Could you send your location please?"
- Всё работает как раньше, просто с 7-секундной задержкой

### ❌ Неправильное поведение:

- Бот не отвечает вообще
- Бот отвечает сразу (без задержки)

---

## ✅ ТЕСТ 4: Множественные сообщения с датой и временем

### Шаги:

1. Пройдите бронирование до момента выбора времени
2. Когда бот спросит "When would you like to book?", отправьте **быстро**:
   ```
   tomorrow
   ```
   (подождите 4 секунды)
   ```
   around 3pm
   ```
   (подождите 3 секунды)
   ```
   is it 90 minutes?
   ```

### ✅ Ожидаемое поведение:

- Бот молчит 7 секунд после последнего сообщения
- Бот обрабатывает все три сообщения вместе
- Бот понимает:
  - Дата: завтра
  - Время: 3pm
  - Вопрос о длительности
- Бот отвечает на вопрос И предлагает слоты

### ❌ Неправильное поведение:

- Бот пропустил вопрос "is it 90 minutes?"
- Бот не понял время "3pm"

## ✅ ТЕСТ 5: Локация + номер виллы одновременно

### Шаги:

1. Пройдите до момента отправки локации
2. Отправьте GPS локацию (через кнопку "Location" в Telegram)
3. **СРАЗУ** (в течение 2 секунд) отправьте:
   ```
   villa 25
   ```

### ✅ Ожидаемое поведение:

- Бот сохраняет GPS координаты
- Бот сохраняет "villa 25"
- Бот **НЕ спрашивает** "What is your villa number?"
- Бот сразу предлагает слоты времени

### ❌ Неправильное поведение:

- Бот спрашивает про номер виллы, хотя клиент уже написал
- В уведомлении нет номера виллы

## 📊 Проверка логов

### Откройте логи:
```bash
tail -f bot.log
```

### Ищите строки:

#### ✅ Правильное поведение:
```
User 123456: добавлено в буфер (1 сообщений)
User 123456: добавлено в буфер (2 сообщений)
User 123456: отменена предыдущая задача обработки
User 123456: добавлено в буфер (3 сообщений)
User 123456: отменена предыдущая задача обработки
User 123456: обработка 3 накопленных сообщений
User 123456: комбинированный текст: Body massage
90 min
please
```

#### ❌ Проблемы:
```
User 123456: обработка 1 накопленных сообщений
```
^ Если всегда 1 сообщение = буферизация не работает!

## 🔍 Как понять что буферизация работает

### Визуальные признаки:

1. **Задержка ответа:**
   - Клиент отправил сообщение
   - Бот показывает "typing..." через 7 секунд
   - Это нормально! Бот ждет другие сообщения

2. **Нет повторных вопросов:**
   - Клиент написал "Body massage" + "90 min"
   - Бот **НЕ спрашивает** "Which duration?"
   - Бот сразу просит локацию

3. **Правильный выбор при изменении решения:**
   - Клиент написал "Body" + "Both"
   - Бот выбрал "Both" (Body + Face)
   - Цена 619.50 AED, не 483 AED

### Логи подтверждают:

- `User {id}: обработка 2 накопленных сообщений` (или 3, или 4)
- `User {id}: комбинированный текст:` содержит несколько строк
- `User {id}: отменена предыдущая задача обработки` (таймер перезапускался)

## ⚠️ Частые ошибки при тестировании

### Ошибка 1: Ждать ответа сразу
**Неправильно:**
```
Клиент: "Body massage"
Клиент: [ждет ответа]
```

**Правильно:**
```
Клиент: "Body massage"
Клиент: "90 min" [сразу, не ждать ответа]
Клиент: "please" [сразу]
[Потом ждать 7 секунд]
```

---

### Ошибка 2: Слишком долго между сообщениями
**Неправильно:**
```
Клиент: "Body massage"
[Пауза 10 секунд]
Клиент: "90 min"
```
^ Бот уже ответил после первого сообщения!

**Правильно:**
```
Клиент: "Body massage"
[Пауза 2-3 секунды]
Клиент: "90 min"
```

---

### Ошибка 3: Не проверять логи
Даже если визуально всё работает, **ВСЕГДА проверяйте логи**:
```bash
tail -50 bot.log | grep "User"
```

Ищите:
- Количество накопленных сообщений (должно быть > 1)
- Комбинированный текст (должен содержать все сообщения)

## 📋 Чеклист успешного теста

- [ ] Бот ждет 7 секунд перед ответом
- [ ] Множественные сообщения обрабатываются вместе
- [ ] В логах видно "обработка N накопленных сообщений" (N > 1)
- [ ] Нет дублирования вопросов
- [ ] Изменение решения работает (последнее сообщение перезаписывает)
- [ ] Одно сообщение тоже работает (просто с задержкой)

## 🎯 Если что-то не работает

### Проблема: Бот отвечает сразу, не ждет 7 секунд

**Проверка:**
```bash
grep "добавлено в буфер" bot.log
```

**Если нет таких строк** → буферизация не работает, нужно проверить код

---

### Проблема: В логах всегда "обработка 1 накопленных сообщений"

**Причина:** Сообщения отправляются слишком медленно (более 7 секунд между ними)

**Решение:** Отправлять быстрее (2-3 секунды между сообщениями)

---

### Проблема: Бот не отвечает вообще

**Проверка:**
```bash
tail -20 bot.log
```

**Ищите ошибки:** `ERROR` или `Traceback`
