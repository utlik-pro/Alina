### 1. VAT (5%) - Противоречие в документации

**Суть проблемы:**
В проекте есть два разных описания как работает VAT:

**Вариант А (из PRICE_LIST.md):**
```
Все платежи включают +5% VAT (cash, card, bank transfer)
Body massage 60 min: 367.50 AED (включая VAT)
```

**Вариант Б (реализовано в коде):**
```
Cash: 350 AED (БЕЗ VAT)
Bank transfer: 367.50 AED (350 + 5% VAT)
```

**Почему это важно:**
- Влияет на ВСЕ цены в системе
- Клиенты могут быть недовольны если ожидали одну цену, а им показали другую
- Бухгалтерия может быть неправильной

**Вопрос 1: Какая логика правильная?**

Нужно знать:
- Что говорит ваша бухгалтерия?
- Что требует налоговая служба ОАЭ?
- Как на самом деле работают ваши администраторы сейчас?

**Примеры для обсуждения:**

Клиент бронирует Body massage 60 min и выбирает **оплату наличными**:
- [ ] Он платит 350 AED (без VAT)
- [ ] Он платит 367.50 AED (с VAT)

Клиент бронирует Body massage 60 min и выбирает **банковский перевод**:
- [ ] Он платит 350 AED (без VAT)
- [ ] Он платит 367.50 AED (с VAT)

---

**Вопрос 2: Что говорит бухгалтерия?**

**Зачем спрашиваю:**
Даже если вы знаете как делаете сейчас, важно подтвердить что это законно.

С 1 августа 2024 в ОАЭ действует обязательный 5% VAT для всех зарегистрированных компаний.

Возможные варианты:
1. **VAT включен в цену всегда** (компания платит VAT государству из своих денег)
2. **VAT добавляется сверху** (клиент платит VAT отдельно)
3. **VAT зависит от способа оплаты** (наличные без VAT как "серая зона")

### 2. YClients API - Доступы к системе

**Что такое YClients:**
Это система управления салонами красоты (CRM). Вы уже используете ее вручную.

**Зачем нужна интеграция:**
Сейчас:
1. Клиент пишет в WhatsApp/Telegram
2. Администратор вручную создает запись в YClients
3. Администратор вручную сообщает клиенту подтверждение

После интеграции:
1. Клиент пишет боту
2. **Бот автоматически** создает запись в YClients
3. **Бот автоматически** отправляет подтверждение

**Вопрос 4: Когда будут credentials?**

Для подключения к YClients API нужны:
- `YCLIENTS_API_KEY` - секретный ключ (как пароль)
- `YCLIENTS_COMPANY_ID` - ID вашей компании в системе

**Где взять:**
1. Зайти в YClients личный кабинет администратора
2. Настройки → API → Создать ключ
3. Скопировать и передать мне

**Почему это критично:**
Без этих ключей бот не может:
- Проверять доступность мастеров
- Создавать реальные записи
- Синхронизировать статусы

Сейчас бот работает в **MOCK режиме** (симуляция, не настоящие данные).

---

**Вопрос 5: Есть ли документация YClients API?**

**Зачем:**
YClients API может иметь особенности:
- Лимиты запросов (сколько раз в минуту можно обращаться)
- Формат данных (как передавать имя, телефон, услугу)
- Webhook'и (уведомления об изменениях)

Если есть документация на русском - будет проще разобраться.

Обычно документация здесь: https://api.yclients.com/

**Вопрос 6: Карточка клиента - автоматически или вручную?**

**Два варианта работы:**

**Вариант А (автоматически):**
1. Клиент первый раз пишет боту
2. Бот **сразу создает** карточку клиента в YClients
3. Все последующие записи привязываются к этой карточке

**Вариант Б (вручную):**
1. Клиент пишет боту

3. **Администратор вручную** создает карточку в YClients
4. Бот получает ID карточки и привязывает запись

**Какой вариант выбрать:**
- Вариант А - быстрее, меньше работы для админа
- Вариант Б - админ контролирует качество данных (проверяет телефон, имя)

**Вопрос 7: Синхронизация статусов**

**Суть проблемы:**
Бронирование может изменяться в двух местах:

**Сценарий 1 (односторонняя синхронизация):**
- Бот создает запись в YClients
- Админ в YClients меняет статус на "Отменено"
- Бот **НЕ знает** об этом изменении

**Сценарий 2 (двусторонняя синхронизация):**
- Бот создает запись в YClients
- Админ в YClients меняет статус на "Отменено"
- Бот **получает уведомление** и обновляет свою базу

**Какой вариант нужен:**
- Односторонняя проще (бот только отправляет данные в YClients)
- Двусторонняя сложнее (нужны webhook'и или постоянная проверка)

### 5. "Потеряшки" (Lost Clients)

**Что это:**
Клиент начал диалог с ботом, но не завершил бронирование.

**Примеры:**
1. Написал "Body massage" → бот показал цены → **клиент исчез**
2. Выбрал услугу → отправил локацию → **клиент не ответил на вопрос о времени**
3. Прошел весь процесс до конца, но не подтвердил → **клиент молчит**

**Вопрос 15: Через сколько считать "потеряшкой"?**

**Варианты:**
- [ ] 30 минут без ответа
- [ ] 1 час без ответа
- [ ] 3 часа без ответа
- [ ] Только если диалог был активный (>3 сообщений)

**Пример:**
Клиент написал "Body massage" в 14:00.
Бот ответил с ценами.
Клиент молчит.

В 15:00 (через 1 час) - считать его "потеряшкой" или подождать еще?

**Вопрос 19: Какой порядок правильный?**

**Логика "локация ДО времени" (как в боте):**
- Сначала проверяем что мы обслуживаем этот район
- Если район слишком далеко → не тратим время на поиск мастера
