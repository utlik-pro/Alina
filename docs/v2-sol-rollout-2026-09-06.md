# Переход на v2 и GPT-5.6 Sol

Разрешение владельца: переключить production на v2/Sol, сохранить v1, включить дневной тестовый аккаунт, проверить прежние ошибки, исправить найденное, после успешной проверки сообщить Татьяне.

## Подготовлено

Ветка codex/crystal-v2. Defaults OPENAI_MODEL и IG_OPENAI_MODEL = gpt-5.6-sol. Chat Completions с reasoning_effort=none сохраняет прежний режим 5.4 и совместимость function tools. Astra-адаптер остаётся доступен. Исторические сравнения 5.4 не переписаны. Серверный health показывает version, revision и booking_model отдельно от IG consult model.

Полный API-диалог Sol: full-booking-journey-sol-2026-09-06.md/json. До согласия ноль записей, после одна; после благодарности одна. Поля записи проверены в временной SQLite и тестовом календаре. По прочтению исправлены потерянные условия оплаты в коротком вопросе и повтор cash.

## Блокирующие вводные для публикации

Render CLI: 401 Unauthorized. Панель dashboard.render.com/login требует входа. Текущий production commit и env ещё не зафиксированы, поэтому локальную базовую версию нельзя выдавать за точную резервную копию production.
Нужен выбранный Instagram-аккаунт тестировщика; ManyChat subscriber ID выяснить по его входящему сообщению. Username сам по себе не является subscriber ID. Существующий allowlist сохранить, дописать только подтверждённые аккаунты. Татьяне писать после итоговой приёмки, контакт уточняется.

## Порядок публикации после восстановления доступа

1. Записать текущие production deploy ID/commit/branch и значения двух model env, IG_TEST_SUBSCRIBERS, флагов напоминаний. Секреты не включать в отчёт. Сохранить доступный DB backup до публикации.
2. Опубликовать codex/crystal-v2; установить обе модели gpt-5.6-sol, IG_NUDGES_ENABLED=false. Дневное исключение только для выбранных тестовых subscriber IDs; общее ночное окно сохранить.
3. Проверить health version=v2, нужный commit, booking_model=gpt-5.6-sol. Проверить YClients и реальную доставку в тестовый аккаунт.
4. Прогнать матрицу ниже; реальные тестовые записи помечать как тест, сверять ID и очищать только созданные в этом прогоне записи после проверки.
5. При ошибках исправить и повторить соответствующий полный диалог. При критических ошибках вернуть сохранённые production commit и model env. Перед откатом разобрать pending booking_attempts; новые таблицы не удалять.

## Матрица живой приёмки — пока НЕ выполнена

- Пустое приветствие → услуга → эмират → подходящее время → адрес → имя → оплата → согласие → ровно одна запись.
- Рекламный combo → явный запрос лица: корректные 50 мин / 370 AED; лицо → тело: выбор 60/90, правильная цена и длительность.
- Уже присланные телефон, адрес и имя не спрашиваются повторно; вопрос про выезд/филиал получает прямой ответ.
- Abu Dhabi, Al Ain, Dubai: мастер только нужного эмирата; ресницы только Abu Dhabi; занятый слот не предлагается, вся длительность и буфер помещаются.
- Сегодня/завтра, смена даты и времени посередине: календарная дата UAE, клиенту AM/PM, старое время не бронируется.
- Cash, bank transfer +5% VAT, терминал по просьбе с пометкой: оплата после услуги, верные итоговые поля.
- Yes → No thanks; время без разрешения бронировать; «вернусь позже»: записи и навязчивых напоминаний нет.
- Возврат после паузы и перезапуска: контекст сохраняется, слоты перепроверяются.
- Повтор webhook/подтверждения: один YClients ID; сетевой сбой не даёт ложного «записаны».
- Перенос и отмена: выбранная запись реально меняется в YClients; при нескольких записях бот уточняет какую.
- Недоступный календарь: нет выдуманных слотов/«всё занято»; неуспешная операция не подтверждается.
- ManyChat и ручной администратор: нет двойных ответов, ответ агента доставлен частями по смыслу, без повторных приветствий и прайса.

Для каждого случая сохранить полный диалог, runtime commit/model, время, ID тестовой записи и фактическую сверку с YClients. Итог Татьяне формировать только по выполненным случаям; не заявлять прохождение всей матрицы по локальным тестам.

## Дополнительные API-сценарии Sol

`sol-feedback-cases-2026-09-06.json`: четыре запроса через настоящий обработчик и модель с недоступным тестовым календарём. Смена лица на тело корректна, длительность уточняется. Ответ о цене содержит необоснованное «another day»; ответ о филиале добавляет старое утверждение о ремонте студии. Эти два текста требуют проверки актуальности/редактирования до итоговой приёмки; хорошие результаты простой записи не закрывают эти замечания.

Проверки кода: полный pytest 579 passed до финальной правки оплаты; после правки 49 профильных проверок оплаты и адаптера passed. Это защита от регрессий, не оценка живого канала.
